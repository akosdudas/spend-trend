# 07 — UX

Screens and workflows. The UI is a local app in a native window (`08-tech-stack.md`).

## 1. Shell

- Opens to the **Dashboard** (saved views).
- A persistent sidebar switches sections. Single local user; no login.

## 2. Screens

### 2.1 Dashboard
Renders saved views as tables and charts in a flow grid (each at its `width`, left-to-right,
wrapping). Per-view width and up/down reorder; add a view; shows the needs-attention count.

### 2.2 Analyze
The builder (`06`): group-by / measure / filter / chart type, with live table + chart and
**Save as view**.

### 2.3 Data (spreadsheet — import + edit)
The core working screen: a spreadsheet of the current year's rows, where importing and editing
recent data are one activity.

- **Columns** = the transaction fields (`01`). Sort/filter by any (incl. group and merchant).
- **Inline edits**: `type`, `category`, `amount`, `notes`; delete a row. No dialog.
- **Add cash row**: type a new line (`03`).
- **Split a row**: a modal (`03`).
- **Import files**: add CSVs (a profile each); parsed rows appear as staged rows in the grid,
 auto-categorized; edit inline; **commit** appends non-skipped rows. May commit with rows still
 uncategorized.
- **Needs-attention filter**: uncategorized rows, to resolve the few unknowns anytime.
- **Make a rule** from a row: a modal (`04`).

### 2.4 Profiles
List of bank profiles. Edited as JSON (`03`) with a **Test parse** action that previews how a
sample CSV normalizes before importing.

### 2.5 Rules
Manage rules — each is `pattern → type (income/expense/skip) + category` (`01`). No
match-type/priority/active; delete to disable. Matching is substring, longest wins (`04`).
Rules apply at import.

### 2.6 Groups
Manage the **shared expense** `category → group` map (`01`) — the current working draft for open
years; assign each expense category to a group; unmapped categories are surfaced. Editing never
touches transactions, and prune it freely once a year is closed. A closed year keeps its own
`groups.json` snapshot; regrouping that year is a local edit to that file (like renaming a
category, this is an external file edit — `01`).

### 2.7 Historical
Legacy years are `data/<year>/summary.csv` files written by hand (`05`). Read-only view of past
annual sums; load warnings for unmapped categories or malformed cells.

### 2.8 Settings
- **Data folder** — shows the current data home (read from the pointer file, `08`). Changing it
 is a file edit or launcher argument, not an in-app picker.
- **Close / Reopen a year** — compile `summary.csv`, or delete it to edit live again (`02`).
- Currency is set per bank profile, not here. Saves are atomic; no backups.

## 3. Workflows

- **Setup** — create the data home + pointer file (setup script, by hand, or `--data-dir`); this
 scaffolds `config/` + `data/`.
- **Monthly import** — Data → import files → fix the easy rows, filter to uncategorized for the
 rest → commit (leftover unknowns commit as uncategorized) → check the Dashboard.
- **New bank** — add a profile JSON → Test parse against a sample → import.
- **Tune categorization** — add/edit a rule; it applies to the next import (past rows edited by
 hand).
- **Year-end** — optionally close an old, settled year.

## 4. Principles

- Skips and deletes are confirmed before commit; closing a year is reversible.
- Every automatic decision is visible and overridable per row before commit.
- Honest granularity: summarised years are shown annually, not faked to monthly.
